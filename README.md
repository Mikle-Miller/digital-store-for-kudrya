# Магазин цифровых товаров

Это проект платформы для продажи цифровых ключей, подписок и гифт-карт. Главная смысл проекта - абсолютная устойчивость к сбоям и гонкам (race conditions) при высоких нагрузках.

## Почему я выбрал такой стек такой стек?

-Laravel 12 (PHP 8.2) — надёжный фреймворк с отличной встроенной работой с фоновыми очередями (что очень важно для асинхронной выдачи).

-PostgreSQL 16 - выбран специально из-за поддержки блокировок `SKIP LOCKED`. Это позволяет параллельным процессам не ждать друг друга при поиске свободных ключей.

-Redis 7 — быстрый брокер сообщений для очередей Laravel.

-Vanilla JS/HTML/CSS — лёгкий фронтенд без перегруза тяжёлыми фреймворками, но с отзывчивым интерфейсом (было такое пожелание в ТЗ).

##  Как обеспечивается защита и отказоустойчивость?

Система построена вокруг концепции двухуровневой идемпотентности:

1. Защита на уровне вебхуков:

   Если платёжная система пришлёт 50 одинаковых вебхуков об оплате одновременно, сработает ограничение на уровне БД (`INSERT ... ON CONFLICT DO NOTHING`). Только первый вебхук запустит процесс выдачи, остальные тихо получат ответ `duplicate`.

2. Атомарная выдача ключей:

   Фоновый воркер ищет свободный ключ запросом `SELECT FOR UPDATE SKIP LOCKED`. Это гарантирует, что один и тот же ключ физически невозможно выдать двум разным покупателям, сколько бы воркеров ни работало параллельно.

3. Лимиты промокодов:

   Списание лимита промокода происходит строго одним атомарным запросом к БД (`UPDATE ... used = used + 1 WHERE used < max_uses`).

4. Умное восстановление:

   Если ключи закончились, система не падает с ошибкой. Заказ мягко переходит в статус `out_of_stock`. После того как администратор добавит ключи в базу, заказ можно "протолкнуть" дальше вручную.

## 🚀 Быстрый старт

```bash
# 1. Склонировать репозиторий и настроить окружение
git clone https://github.com/Mikle-Miller/digital-store-for-kudrya.git ggsel-shop
cd ggsel-shop
cp .env.example .env

# 2. Поднять контейнеры (БД, Redis, PHP, Nginx, Worker)
docker compose up --build -d

# 3. Накатить миграции и заполнить базу (50 ключей, 4 промокода)
docker compose exec app php artisan migrate --seed
```

-Витрина магазина: [http://localhost:8080](http://localhost:8080)
-Панель управления (тестовая): [http://localhost:8080/admin.html](http://localhost:8080/admin.html)

url сайта: http://digital-store.duckdns.org

## 🕹 Ручное тестирование (UI)

Вы можете протестировать логику восстановления прямо из браузера:
1. Зайдите в Панель управления и нажмите кнопку Удалить все ключи, или просто можно насоздавать несколько покупок, например Xbox Gift Card 1500 (там вроде 3 ключа).
2. Перейдите на Витрину магазина и совершите покупку (можно применить промокоды, например `WELCOME10` или `ONCEONLY`).
3. Заказ повиснет в статусе `out_of_stock` (ожидает пополнения).
4. Вернитесь в админку, нажмите **«Добавить 60 ключей»**.
5. Нажмите кнопку **«Retry»** рядом с зависшим заказом — система найдёт свободный ключ и успешно выдаст его (идемпотентно).

## 🧪 Как запустить автоматические тесты?

В проекте есть специальный скрипт, который автоматически "атакует" сервер множеством параллельных запросов и проверяет выполнение всех **5 критериев приёмки** (проверка на гонки, пустой пул, лимиты).

**Запуск локально:**
```powershell
# Windows
powershell -ExecutionPolicy Bypass -File tests\acceptance-test.ps1

# Mac / Linux
bash tests/acceptance-test.sh
```

**Запуск проверки на боевом сервере:**
```powershell
# Windows
powershell -ExecutionPolicy Bypass -File tests\acceptance-test.ps1 -BaseUrl http://digital-store.duckdns.org -Label PROD

# Mac / Linux
bash tests/acceptance-test.sh http://digital-store.duckdns.org PROD
```

Ожидаемый результат тестов: `PASS: 7 | FAIL: 0` (Все проверки пройдены успешно).
